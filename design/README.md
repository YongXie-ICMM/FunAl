# 这门课是怎么设计出来的

这里是课程的设计材料。想改课程内容，**先改 `lesson_spec.md`，再改对应的 `src/levels/*.js`**。

| 文件 | 是什么 |
|---|---|
| `lesson_spec.md` | 逐屏教学脚本：每屏的目标、学习者的动作、每句文案、每个错误答案的诊断、三级提示。 |
| `plans/plan_*.json` | 五份**独立**的课程设计，各用一种教学法主轴（苏格拉底式提问、先痛后药、实物隐喻、迁移导向、故事驱动）。最终课程以其中一份为主干，嫁接了其余四份里被评审点名的设计。 |
| `plans/personas.json` | 24 份**模拟学习者走查报告**。三类学习者（14 岁初中生、怕符号的文科研究生、会递归但学不会 DP 的初级程序员）分别走过上面每一份方案，逐屏记录：哪里卡住、哪里想关掉页面、以及**「我会冒出但方案没回答的问题」**。 |

最后那一栏是这份材料里最有用的东西。24 份报告里反复出现的疑问被整理成一张必答清单，最终课程逐条解决，例如：

- 「到第 0 级为什么算 1 种走法？我一步都没走。」（出现 8 次）
- 「为什么非要看最后一步？看第一步不也行吗？」（出现 10 次，而且**看第一步确实也行**——早期方案给的反驳站不住，最终课程改成诚实处理）
- 「这套办法什么时候会失灵？」（程序员型学习者判断一道题能不能用 DP 的唯一标准）
- 「两个来路一样小怎么办？」「凑不出来的格子填什么？」「f(k) 的括号是乘法吗？」

想加一屏或改一屏，建议先读一遍 `personas.json` 里对应位置的卡点，再动手。

## 数字的来源

课程里每一个数字都在 `src/data.js` 里，并由 `tools/verify_answers.py` 从头重算一遍做校验（70 项断言）。改数据后请运行：

```bash
python3 tools/verify_answers.py
```

它不只对答案，还检查课程依赖的性质，例如：过路费楼梯的最省路线**必须**踩上最贵的台阶（否则「躲开贵的」那个陷阱就不成立）、最省路线**唯一**（否则倒推会有两个答案）、以及加了罚款之后旧表给出的价钱**低于任何真实走法**（否则「表算出了一个买不到的价钱」这句话就不成立）。
